# Contract release readiness

## Current state

ACV1-CONTRACTS (issue #5) remains blocked. The maintained [shared-contracts catalog](https://github.com/Jevelopers-neatHack-2026/shared-contracts/blob/c4caaccc2ea63b273eeac17ed89af8ac64f6bbde/docs/contract-catalog.md) is design documentation; the inspected owner trees did not contain executable schemas, generated validators, or the DecisionPort/approval/budget adapters required for fixture conformance. `fixtures/contracts/release.json` records the exact external owner actions without copying those contracts.

The pending descriptor is a harness readiness inventory, not a runtime schema or a new contract authority. A canonical release must come from shared-contracts and carry owner-reviewed consumer handoffs. The v2 verifier checks content hashes, independently trusted owner evidence, every declared runtime schema, the exact JSON Schema property set for each schema/contract/primitive tuple, and a separate fixture mapping for every tuple before it considers execution. It does not generate schemas, infer field aliases, or count coverage tags.

The field extractor accepts only an explicitly declared JSON Schema Draft 2020-12 dialect (`https://json-schema.org/draft/2020-12/schema`) within a bounded subset. It follows local JSON Pointer references and the standard composition, conditional, dependency-schema, `prefixItems`, `items`, `contains`, and `unevaluatedItems` applicators. Positional tuple fields use numeric path components and general array elements use `/*`. External/dynamic references, legacy dialects and applicators, unknown keywords, `patternProperties`, open/dynamic `additionalProperties` or `unevaluatedProperties`, and open item schemas are unsupported and fail closed. Traversal is bounded to 20,000 work steps, 2,048 reference expansions, 10,000 unique fields, 4,096 bytes per path, and 1 MiB total path bytes. A limit returns a typed blocker before adapter execution. These are parser safety limits, not owner acceptance targets.

The local adapter protocol is `agent-creative.contract-fixture-adapter/v2`. It is an internal tool exchange, not a DecisionPort, application port, or approval authority. The adapter receives exact schema/fixture paths and hashes but never receives expected outcomes or expected serialization hashes. Optional adapter dependencies must be declared by relative path and SHA-256; undeclared package files are not mounted. Its independently evidenced bytes must return typed case identities, observed input hashes, outcomes, and actual serialized bytes; the parent hashes those bytes. A response that echoes expected values or omits observed bytes fails.

`offline_attested` and other local status strings do not establish isolation or owner provenance. The runner requires an owner-evidence index outside the repository and an exact SHA-256 supplied independently through protected runner configuration (`ACV1_OWNER_EVIDENCE_INDEX` and `ACV1_OWNER_EVIDENCE_SHA256`, or explicit CLI arguments). The index and each evidence document bind accepted owner decisions to exact subject hashes and revisions. This is a pinned transport for already published owner evidence, not a replacement approval authority. A path, URL, hash, revision, or `accepted` value inside the release manifest cannot self-authenticate.

Adapter execution is skipped unless a reviewed Linux bubblewrap runtime can isolate the Python runtime, use separate network and PID namespaces, drop capabilities, and pass synthetic filesystem/socket/child-process canaries. Canary failure diagnostics include a bounded, path-redacted summary of the synthetic subprocess result; package/fixture contents and raw owner-adapter stderr are not published. After each artifact is re-read and matched to its pinned SHA-256, the adapter, explicitly declared dependencies, runtime schemas, field inventory, and fixture bytes are copied into sealed in-memory files. Bubblewrap places adapter/schemas/inventory/fixtures in a fresh read-only `/release` tree and declared dependencies in a separate read-only `/acv1-dependencies` tree. A trusted `-I -B -S` bootstrap adds only that sealed dependency tree to `sys.path` and executes the sealed adapter bytes; host package paths, the current directory, site packages, and undeclared package files are not import roots. Mutable package paths are never mounted or reopened for execution. The runner bounds input/output and timeout and kills the process group on timeout or output overflow. A platform without the sealed-snapshot runtime or enforceable sandbox fails closed with an execution prerequisite; the macOS `sandbox-exec` command is not treated as a supported security boundary. `--offline` alone is not an isolation guarantee. This verifier makes no network/provider calls itself. An offline fixture pass proves only owner fixture conformance; producer/consumer runtime integration, server authorization, ledger behavior, live access, and global acceptance remain separate.

## Crosswalk required from owners

The published descriptor must include the owner-generated machine-readable field inventory pinned to each schema artifact hash. Every declared runtime schema has at least one inventory tuple, every inventoried schema/contract/primitive tuple has a fixture mapping, and each tuple has one accepted row per serialized field. The verifier compares inventory paths with statically declared JSON Schema properties rather than trusting the inventory's own list. Each row records canonical field spelling, schema SHA-256, meaning, producer role and leaf, consumer role and leaf, trusted derivation, omitted-versus-unknown behavior, precision/rounding (or owner-approved not-applicable reason), privacy/retention, compatibility rule, and independently evidenced producer/consumer reviews. A field alias never substitutes for a canonical field path. All listed schemas are runtime schemas; auxiliary files belong in explicit adapter dependencies and cannot be counted as runtime coverage.

The field set includes the catalog common envelope (`schema_version`, `event_id`, `tenant_id`, `project_id`, `correlation_id`, `producer`, `occurred_at`, `ingested_at`, `environment`, `billing_mode`, `source_refs`) and applicable workflow/run/order/design identifiers. It also covers separate `logical_operation_id`, `billable_attempt_id`, `transport_attempt_id`, `provider_request_id`, and source observation identity; immutable facts/package and artifact/version/hash bindings; externally authenticated actor/scope/action/expiry/revocation; reservation binding/lifecycle; decision/question/policy/model identities; and trace/usage references. Unknown or unavailable values must follow the canonical owner's omitted/explicit-unknown semantics.

The required issue #5 cases stay unchanged: `current_valid`, `current_invalid`, `supported_older_version`, `unsupported_major_version`, `unknown_additive_fields`, `forged_tenant_project_scope`, `approval_artifact_fact_mismatch`, `approval_invalid_actor_action_expiry_revocation_replay`, `changed_fact_hash_without_artwork_change`, `changed_artifact_bytes_without_hash_change`, `logical_billable_transport_identity_swap`, `billable_id_reused_for_new_billed_request`, `duplicate_usage_observation`, `provider_request_id_unavailable`, `unknown_usage_as_zero`, `expired_lease_with_unresolved_dispatch`, `fractional_subcent_usage`, `simulated_sales_live_inference_billing`, `provenance_conflict`, `unapproved_asset`, `malformed_control`, `wrong_project_result`, `cancelled_deadline`, `unsupported_field_alias`, `old_consumer_additive_field`, `choice_actual_provider_shape`, `score_actual_provider_shape`, and `noul_actual_provider_shape`. The owner fixture crosswalk maps every case to its actual schema, contract, primitive, and pinned fixture bytes. A fixture success cannot claim runtime authorization, ledger, or producer/consumer behavior.

## Compatibility and migration

The owner must declare whether unknown additive fields are preserved or ignored, publish current and supported older consumer fixtures, and reject unsupported major versions. Breaking changes require a new supported version and a migration plan. Generated package revisions must be pinned and tested with affected producers and consumers. The harness makes no silent migration or model-alias policy change and does not infer aliases where owners disagree.

The app compatibility decision remains external and must preserve trusted server-derived scope plus exact approval/hash binding. Budget and approval authority remain with their owning systems. No financial ledger, authorization service, UI, or provider adapter is implemented here.

At this revision the command must exit `2` with `status=blocked`, because the canonical release and all nine external owner decisions are absent. Diagnostics identify the exact owner and action and contain no fixture/customer content. A future zero exit means only `offline_conformance_passed`; it cannot close issue #5 or satisfy CON-01/02/03, ART-02, FIN-01/02/03/04/07/10, BUD-01/02/03, or global Agent & Creative v1 acceptance. Runtime API/review enforcement remains with AH-02/AH-07; reservation contention and ledger behavior remain with AH-09 and cost-intelligence; consumer execution remains with the implementation leaves.

The release descriptor moved from v1 to v2 because v1 allowed self-asserted owner metadata and did not bind exact schema fields, fixture mappings, and observed serialized bytes. V1 descriptors are not silently migrated. The actual canonical schemas, serialization rules, owner decisions, and fixtures remain external; there is no copied or locally invented replacement. Current local unit tests use only temporary synthetic schemas/fixtures and never mark release readiness.

The CI workflow separately verifies the complete multi-schema synthetic CLI path through the sealed snapshot and native sandbox, plus adversarial rejection and path-substitution tests. The explicit `--test-only-synthetic` mode requires a test-marked manifest and evidence index; its result is always `status=synthetic_test_only_validation_passed`, `ready=false`, and `owner_evidence_verified=false`. These test-only files do not represent owner publication or approval. CI then runs the checked-in release command in a clean offline environment and requires its exact `exit 2`, `status=blocked`, `ready=false`, nine owner-action diagnostics, and missing trusted-evidence diagnostic. CI uploads a classified JSON artifact whose readiness remains blocked. A green implementation-check job means only that the prerequisite tooling returned the known pending result; it is not a canonical conformance pass. The Linux checker job installs the Ubuntu `bubblewrap` package, requires the real filesystem/shadow-write/socket/descendant and sealed-snapshot tests, and fails if any test skips. Local macOS runs use mocked cases for unsupported-platform behavior and report native Linux tests as skipped when bubblewrap is unavailable; that skip is not sandbox conformance evidence.
