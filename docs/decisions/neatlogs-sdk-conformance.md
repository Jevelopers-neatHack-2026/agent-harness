# Neatlogs local SDK mapping conformance

This document records a local implementation prerequisite for ACV1-AH10. It proves that projected telemetry records can be mapped through the pinned Neatlogs SDK into a bounded local collector. This local path does not itself show service ingestion or Entire provenance, or complete AH-10, EVAL-03, or EVAL-04. The separate master records SPN-01 and SPN-02 as owner-accepted on 2026-10-11; those decisions rely on external evidence and are not established by this local SDK work. SPN-01's qualified record is for a `getticketstub.com` operational exporter run. It does not accept this repository's durable event file-outbox path or establish full harness integration. See the [qualified Neatlogs acceptance record](https://github.com/Jevelopers-neatHack-2026/integration-evals/blob/56018576a9450a2bb46aa55ed3b2f9d9ae97e50d/evidence/neatlogs/2026-10-11/README.md) and the exact [master checklist snapshot](https://github.com/Jevelopers-neatHack-2026/integration-evals/blob/56018576a9450a2bb46aa55ed3b2f9d9ae97e50d/planning/acceptance-checklist.md#spn-02-entire-use).

## Pinned package and public API

The runtime requires Node `22.23.3`. `package.json` pins `neatlogs` to exactly `1.1.28`; the v3 lockfile records the complete dependency graph with resolved URLs, package versions and integrity strings. The SDK evidence inventory must match every lockfile package path. Existing SDK dependencies retain their declared license metadata. The additional private, development-only creative-engine contract-test package has no declared license and is recorded honestly as `license: null` / `unknown_private_development`; this is not license clearance or a change to any independent acceptance gate. No OpenTelemetry package is directly imported by the harness. The strict TypeScript check imports the public `Client`, `trace`, `ClientOptions`, and `ClientOptions['spanExporter']` types from `neatlogs`.

The locally exercised path creates an actual `Client`, uses `trace` for each projected event, and supplies an owned bounded `spanExporter`. The fixed workflow name, sample rate `1`, `debug: false`, `captureLogs: false`, `uploadAuthority: false`, `disableExport: false`, synchronous owned mask, and `https://offline.invalid/v1/traces` option are explicit. The only API key is the literal synthetic placeholder `offline-synthetic-placeholder-no-service-access`, required by the SDK when its export pipeline is enabled. The custom exporter is local; no OTLP/default exporter is selected. The SDK is imported only after input and ambient-environment checks pass.

No `init()`, `flushAll()`, prompt API, log capture, framework integration, provider registration, global OpenTelemetry provider, process signal hook, or monkeypatch is installed. Neatlogs does create namespaced global symbols; the isolated lifecycle test observes and documents `neatlogs.identity.storage`, `neatlogs.active_client_async_local_storage`, `neatlogs.private_span_async_local_storage`, `neatlogs.private_provider_state`, `neatlogs.media-runtime.v1`, and `neatlogs.log_runtime_state`. These symbols are not evidence that the harness registered a global OpenTelemetry provider.

## Projection, mapping, and privacy boundary

The input is limited to already projected `agent-harness.telemetry.v1` records. The boundary revalidates the exact ten own-data fields, `tok1_` HMAC token format, event and state enums, safe integers, strict sequence order, 32-record maximum, 1 KiB per-record bound, and 64 KiB batch bound. Proxies, accessors, cyclic or extra objects, malformed tokens, unsupported enums, and oversized/out-of-order batches fail before SDK import.

Each source event becomes one static `WORKFLOW` trace named `agent_harness.workflow_event`, with only allowlisted token, sequence, revision, event type, state/null flags, fence, and original source time attributes. The SDK-generated `neatlogs.trace.complete` span is retained as a separately counted marker. The source event time stays data; SDK duration is local export preparation time. Replays retain the projected event token but do not claim stable SDK-generated trace IDs, full workflow topology, or remote deduplication.

The synchronous total mask catches exceptions and returns `null` for invalid or undefined input. It reconstructs the envelope, resource, attributes, status, and empty event/link lists; it does not return a mutated original. Every returned object and nested collection, including generated empty event/link arrays, is frozen before capture. It accepts the pinned SDK's fixed resource values, generated trace/span identifiers, expected structural fields, allowlisted source attributes, and static completion marker. It drops input/output/error content, ambient verification markers, session/user metadata, unapproved resource fields, and unknown envelope keys. Capture verifies exact source-record identity and one completion marker per root before emitting a local artifact.

Tests seed synthetic raw-ID, private-URL, secret-suffix, customer-text, error-text, and session-marker canaries in durable workflow fixtures and SDK input/output/error fields. They assert the canaries do not appear in the sanitized capture, child stdout/stderr, or evidence artifact. The isolated SDK regression also records the SDK's `undefined`-mask pass-through behavior using synthetic values, but only as a boolean observation; no raw canary is printed. Production inputs must remain projected HMAC records.

## Bounds, lifecycle, and local result semantics

At most 32 source records produce at most 32 root spans plus 32 completion markers, for a 64-span cap. The actual SDK `batchSize` is 65, one above that admitted cap, so a valid full request cannot cross its automatic export threshold before the request explicitly calls `flush()`. The active request remains latched until public flush and the owned local export callback have completed. Real-SDK tests cover 31 and 32 records at 0 ms and 150 ms callback delays for both successful and failing callbacks, then assert counters and pending work stay unchanged after completion/close. Serialized local capture output is capped at 128 KiB. One preparation request can be active per capture instance; exporter callback delay is capped at 150 ms and preparation timeout at 500 ms. Abort, timeout, changed-record retry, close, and generation tests exercise the max batch barrier and ensure late callbacks cannot satisfy or mutate a later generation. Closing is idempotent and bounded by the SDK's public close API.

Abort controls are brand-checked with the native `AbortSignal.aborted` getter after proxies are rejected. Listener registration/removal use captured `EventTarget` intrinsics, so caller-owned `aborted`, `addEventListener`, or `removeEventListener` overrides are never invoked. Invalid/proxied/forged signals return a static bounded failure before acquiring the request latch. Timer/listener cleanup is nested so the active request is always released; the first abort/timeout/close cause remains stable while owned SDK work drains.

The return value is either a sanitized `captured_local` envelope or a bounded failure code. Trace return, `span.end()`, SDK flush, callback completion, and empty SDK flush are never represented as source acceptance. The result contains no `accepted` or `acceptedCount` field. This local path does not import the durable store, advance its telemetry cursor, acknowledge a financial outbox item, or change authoritative workflow state.

The real-package test projects synthetic events from `DurableWorkflowStore` through the existing HMAC projector, captures them through the real SDK into the custom local exporter, and verifies the original page and cursor remain unchanged. SQLite restart coverage closes the parent's store, then kills isolated children after reopening the actual database before SDK capture, during a delayed real SDK export callback, and after capture. After each kill, the test reopens the same database, compares every table to a pre-kill snapshot, verifies the cursor and unresolved authority hold/outbox, reprojects the same HMAC event tokens, and replays them through a fresh real SDK subprocess.

On this Darwin worktree, SDK conformance subprocesses run with an operating-system `sandbox-exec` policy denying network access. The test environment contains only `TMPDIR` and `NODE_NO_WARNINGS`; production capture checks environment variable names for unsafe `NEATLOGS_*`, `OTEL_*`, and `NODE_OPTIONS` settings without reading or copying their values. Tests use only the synthetic placeholder key. Package registry access was used only to populate the package cache with scripts disabled; subsequent offline bootstrap succeeded.

## Pinned SDK behavior and service-acceptance gap

The implementation and evidence pin the installed Neatlogs package and mapped source files, plus the relevant OpenTelemetry exporter source. The regression records these behaviors in Neatlogs `1.1.28`:

- A mask result of `undefined` passes through the original span data. A throwing mask can invoke the SDK logger with its error. A mask result of `null` drops the span.
- The filtering exporter can return `ExportResultCode.SUCCESS` when every span was filtered out, so an empty flush is not proof of source acceptance.
- The pinned OTLP delegate handles parsed transport `partialSuccess` through a logging response handler and returns SDK success; malformed success-body handling also logs a diagnostic and returns success. The source pins show information loss, not a compatible whole-batch acceptance contract.

The source-pinned partial-success/malformed-body regression is retained. An official-exporter transport execution is pending because doing so here would require a forbidden network path or global transport monkeypatch. No SDK source is patched, no unexported API is used, and no mock receipt is treated as service evidence.

A future service sink remains disconnected until an approved strict transport can expose parsed full-versus-partial acceptance, account for every source span and marker, bound request/response bytes and retries, honor cancellation, and maintain the active-request latch until actual completion. It also needs a durable nonretryable partial-rejection/quarantine policy compatible with the existing telemetry retry behavior. A successful receiver response would still not prove dashboard visibility, retention, correlation correctness, or sponsor acceptance.
